工业界有一个普遍的落差：算法同学能训出指标达标的模型， 但把它变成稳定、可观测、可迭代的线上服务，往往是更难的那一半工作。 这个项目以中文语音识别为载体，把这一半补齐 —— 数据版本 → 训练 → 模型注册 → 容器化 → 编排部署 → 灰度发布 → 漂移监控 → 自动再训练。

02

八层架构，一次看清

请求自上而下穿过八层。点击任意一层查看它解决什么问题、有哪些关键组件；悬停可快速预览。

四个约束决定了这套架构的形状： 音频推理是长耗时请求（同步 HTTP 承载不了）→ 异步队列； 模型加载要 60–180 秒（普通 Web 服务没这个问题）→ 三探针分离； 训练与推理环境容易不一致 → 收敛成单一推理实现； 上线后分布会漂移且劣化滞后 → 在线检测 + 自动再训练。
03

七个代码模块，怎么分工与协作

上一个是概念上的分层，这里是真实代码结构。 依赖关系由源码里的 import 语句实际提取，不是示意图。 悬停模块卡或图上的节点，可高亮它的调用关系。

模块依赖图 调用方向 双向依赖

纵向为层级：越靠下越基础。src/common 被全部 6 个模块依赖， 是唯一的零业务逻辑地基。

一个刻意的"反向依赖"：src.train 与 src.serving 互相调用。 单向分层通常是好事，但这里的两条反向边都是有意为之 —— evaluate.py 复用服务端的推理引擎（消除 training-serving skew）， app.py 复用数据模块的分层抽样与指标函数（保证对照同源）。 代价是打破了单向依赖；收益是消除了两处更危险的静默偏差。 这个取舍是有意识的，不是疏忽。

    06

    四组实验，用数字说话

    E0 是前置条件，不做它后面三组的数字都不可信。每组都给出实际测量结果。

    本轮最硬的结论：PSI 不能作为识别质量的代理指标。 在 12 个漂移场景上实测，PSI 与 CER 的 Spearman 秩相关 ρ = 0.028（p = 0.93） —— 统计上完全不相关。幅度扰动把 PSI 顶到饱和值 12.44 而 CER 只涨 2%； 语速扰动 PSI 仅 0.62 而 CER 涨 2.77 倍。 所以正确结构是：PSI 只触发评估，CER 门禁才决定是否重训/上线。
