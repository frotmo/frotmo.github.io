先建立一个心智模型：操作系统到底在干什么？

在看任何一篇论文之前，先把这张图记住。后面所有内容都是这张图某一格的展开。

操作系统同时在做三件互相拉扯的事，几乎所有「设计取舍」都来自这三者之间的张力：

① 抽象（Abstraction）

把 messy 的硬件包装成好用的概念：

  • CPU → 进程 / 线程
  • 内存 → 虚拟地址空间
  • 磁盘 → 文件与目录
  • 网卡 → socket
② 复用（Multiplexing）

多个程序同时用一份硬件，且互不察觉：

  • 时间复用：调度、上下文切换
  • 空间复用：页表、内存分配
  • 竞争：锁、原子操作
③ 隔离（Isolation）

一个程序出错/作恶不能影响别人：

  • 地址空间隔离（页表）
  • 特权级隔离（U / S mode）
  • 系统调用是唯一入口
⚖️ 由此产生的永恒张力
  • 抽象越强 → 越方便，但越慢（见微内核论文）
  • 隔离越强 → 越安全，但开销越大（见 Firecracker / gVisor 论文）
  • 共享越多 → 越快，但越容易竞争（见 lock lab / RCU 论文）
  • 硬件越激进优化 → 越快，但可能泄漏（见 Meltdown 论文）
给零基础读者的一句话 学操作系统不是背概念，而是反复问：这个机制如果不做会怎样？做了又要付出什么代价？ 本站在每一节都会同时给出这两半。

阶段 0 · 准备（1–2 天）

补三样东西：C 语言指针、RISC-V 汇编、gdb

课程不教这些，但它们是门槛。你只需要能读懂指针、结构体、函数调用栈，以及能在 gdb 里打断点看寄存器。

K&R 第 5–6 章 xv6 book Ch.1 ecall / sret / satp 是什么 → Lab: util
阶段 1 · 用户视角（第 1–2 周）

先当「使用者」：系统调用就是操作系统的 API

在 util lab 里写 sleep / find / memdump，你会第一次意识到：程序能做的事，完全由内核提供的那几十个系统调用决定。 接着 syscall lab 让你亲手加一个系统调用，看清这层边界是怎么实现的。

Lab: util Lab: syscall 论文: Janus（系统调用拦截） Notes: 系统调用与 trap xv6 Ch.2 / Ch.4
阶段 2 · 进内核：地址空间与陷阱（第 3–6 周）

本课程最硬的一段：页表、trap、页错误

pgtbl 让你把页表打印出来看；traps 让你理解用户态/内核态怎么切换； cow 让你第一次用「页错误」当编程工具。这三关过了，后面就是应用。

Lab: pgtbl Lab: traps Lab: cow 论文: Superpages 论文: Appel & Li Notes: 页表 Notes: 页错误
阶段 3 · 并发与设备（第 7–10 周）

多核时代真正的难点：竞争、锁、中断

lock lab 让你量化锁竞争并重构数据结构；net lab 让你写真正的 DMA 环形描述符驱动。 配合 Read-copy-update 与 receive livelock 两篇论文，你会理解「性能问题往往不是算法问题，而是结构问题」。

fs 让你改 inode 结构并处理崩溃恢复；mmap 让你把「用户态页错误处理」这套思想落地。 最后的论文把视野拉到现代：容器、微 VM、eBPF、侧信道。

零基础术语速查（遇到就回来查）

内核态 / 用户态
CPU 的两种特权级别。内核态能执行特权指令、访问全部内存；用户态不行。RISC-V 里叫 S mode / U mode。
trap（陷阱）
任何「从用户态跳进内核」的事件统称：系统调用（ecall）、中断（设备）、异常（页错误、非法指令）。
页表（page table）
一张由内核维护、由硬件查的「虚拟地址 → 物理地址」翻译表。它是进程隔离的物理基础。
PTE
页表项。除了物理页号，还带 V/R/W/X/U/A/D 等权限与状态位。
TLB
页表的缓存。页表改了必须同步失效它（sfence.vma），这是新手最容易漏的一步。
页错误（page fault）
访问了未映射或无权限的地址。它不只是「出错」，更是现代 OS 实现懒加载 / COW / mmap 的核心手段。
上下文切换
保存当前线程的寄存器、恢复另一个线程的寄存器。xv6 里由 swtch() 完成。
自旋锁（spinlock）
拿不到锁就一直循环重试。临界区短、且不能在持有它的情况下睡眠时使用。
竞争（race）
两个执行流同时访问同一份数据、且至少一个是写，结果依赖时序。死锁、丢失唤醒都属于它的变体。
DMA
设备不经过 CPU，直接把数据搬到内存。驱动要提供「描述符环」告诉设备往哪搬。
inode
文件的「元数据 + 数据块位置」记录。目录只是「名字 → inode 号」的表。
WAL / 日志
先把改动写进日志区、commit 之后再落原位，保证崩溃后能重放，从而维持文件系统一致性。
